4. BIOS settings

F2 at power-on. Everything below is in the normal menus — no BIOS modding is required or recommended.

CFG Lock (MSR 0xE2): no action. AppleXcpmCfgLock=True is already set in the config. If you ever want to do it properly, ControlMsrE2.efi ships in the OpenCore package.

DVMT: leave the BIOS alone. Default 32 MB is fine at 1080p; the config already lies about stolen memory (framebuffer-stolenmem = 63 MB) if it becomes necessary.

5. Installation

  1. F12 at power-on → choose the USB stick → OpenCore.
  2. Picker shows macOS Base System. Boot it. Verbose text, then a slow VESA desktop — no acceleration yet, this is normal.
  3. Connect to Wi-Fi (AirportItlwm is loaded, so the menu exists). The installer downloads macOS from Apple.
  4. Open Disk Utility → View → Show All Devices → select the SN530 → Erase → APFS, GUID.
  5. Close, run Install macOS Tahoe. It installs roughly 26.0 and reboots several times — keep choosing the USB, then the macOS entry.
  6. After setup, run System Settings → General → Software Update and install 26.7.1 (25G241).

The acceleration stack is built and byte-checked against 26.7.1 (25G241). Do not apply it before that update, and do not jump to a later major version afterwards.

6. Post-install: acceleration

Everything in this section happens on macOS, after 26.7.1 is running. The install EFI deliberately contains no NootedGreen — it cannot load before the driver stack exists.

6.1 Get the stack

cd ~
git clone https://github.com/JulioNectar/Hackintosh-XPS13Plus-IrisXe-Tahoe
cd Hackintosh-XPS13Plus-IrisXe-Tahoe
zsh install.sh

install.sh installs Apple's Tiger Lake driver kexts into /Library/Extensions and sets the accelerator's IOPCIPrimaryMatch to 0x9a498086, so the stock TGL driver binds your 9A49.

6.2 Add the two kexts

cp -R /Volumes/MACINSTALL/post-install/NootedGreen.kext  /Volumes/EFI/EFI/OC/Kexts/
cp -R /Volumes/MACINSTALL/post-install/AMFIPass.kext     /Volumes/EFI/EFI/OC/Kexts/

Then add both to Kernel → Add in config.plist (ProperTree, Ctrl+R snapshot), after Lilu and WhateverGreen.

6.3 Boot arguments

keepsyms=1 debug=0x100 alcid=11 amfi_get_out_of_my_way=1 \
-allow3d -disablegfxfirmware ngreen-eu=80 ngreen-l3=6

Removed from the installer set: -v and -igfxvesa. Everything else stays. The two ngreen-eu / ngreen-l3 values are the 80 EU / 6 L3-bank description of your exact part; the repo documents a native i5-1135G7 9A49 (HP Dragonfly G2) needing precisely these.

6.4 Verify

system_profiler SPDisplaysDataType        # "Intel Iris Xe Graphics", Metal: Supported
ioreg -l | grep -i IOAccelerator
sysctl -n machdep.xcpm.mode                # 1

7. GPU performance

You are on the same driver stack as the reference project: Apple's own Tiger Lake driver, patched in memory by NootedGreen. There is no second, faster path for Iris Xe on Tahoe.

LeverEffect
ngreen-eu=80 ngreen-l3=6describes your real topology. Without it NootedGreen assumes 96 EU / 8 banks, which causes rendering artifacts on 80 EU parts.
-allow3denables the 3D engine path
-disablegfxfirmwareGuC-less host scheduling (required on this stack)
-ngreengva + VA pluginhardware H.264/HEVC decode; the single biggest real-world speedup for video
GPU clock~1300 MHz under load; requests RP0 1500 MHz but package power caps it

Do not copy the XPS boot-args verbatim. ngreenpm=22, ngreen-dmc=adlp, -ngreentglwithgfx, ngreenV142=3, ngreenblmax=17777 are Raptor Lake specifics. On native Tiger Lake they are wrong or meaningless.

OpenGL will stay software-rendered. That is a property of Tahoe, not of your config. Anything using Metal (Games via MoltenVK, Safari/Chrome compositing, Photos, Final Cut-style apps) is hardware accelerated.

8. CPU performance

Your CPU needs no patches. It is a plain 4-core Tiger Lake with no E-cores, so:

  • XCPM works natively — enabled by SSDT-PLUG (plugin-type=1), which is already in the EFI.
  • AppleXcpmCfgLock=True is set, so the locked MSR 0xE2 does not block power management.
  • Do not add -ngreenpm. It exists to fix hybrid 12th/13th-gen P-core turbo limits and patches XCPM code verified on those CPUs. On Tiger Lake it is unnecessary and risky.
  • CpuTopologyRebuild is not needed (no E-cores).

Verify turbo is being reached:

sysctl -n hw.ncpu                       # 8
sysctl -n machdep.xcpm.mode             # 1
pmset -g therm                          # CPU_Speed_Limit should sit at 100
sudo powermetrics --samplers cpu_power -n 1 | head -20

Sustained performance on this chassis is thermal, not software: a 15 W Tiger Lake in a thin convertible will settle around 2.4–3.0 GHz all-core. A repaste and a laptop stand do more than any config key.

9. Pen, touchscreen, touchpad

All three devices sit on I2C and are already handled by the ACPI in your firmware:

DeviceACPI pathDeclared interrupt
Touchpad ELAN06FA\_SB.PC00.I2C0.TPD0GpioInt on \_SB.GPI0, pin written at runtime by _INI
Touchscreen / pen WACF2200\_SB.PC00.I2C1.TPD0same pattern

Because the interrupt pin is declared (the firmware patches the pin number into the resource template at _INI time), no custom SSDT-I2C is required. That is the usual failure point on other Lenovo models, and it does not apply here.

If the pen does not respond

  1. Check the kext bound: ioreg -l | grep -iE "VoodooI2C|VoodooI2CHID"
  2. Check the device was found: ioreg -l | grep -iE "WACF|ELAN06|HIDDigitizer"
  3. Add -vi2c-force-polling to boot-args (drops interrupts, costs battery, proves the bus works).
  4. If polling makes it work but interrupts do not, the OpCore SSDT-GPI0 + GPI0 _STA → XSTA rename is the thing to revisit.
  5. Gestures (one-finger scroll, pen mode, right-click hold) are a user-space extra in the repo: zsh tools/build-xe-toque.sh.

Pen pressure and tilt depend on the HID report descriptor being passed through untouched by VoodooI2CHID. Expect the pen to move the pointer first; pressure sensitivity in drawing apps is the second thing to verify, in an app that reports it (Krita, Blender, or a tablet tester).

11. Recovery and rollback

  • Windows is gone from the internal disk. There is no Windows partition to fall back to.
  • The USB holds a working OpenCore + recovery. Keep it — it is your rescue disk.
  • macOS Recovery: hold Cmd+R at the OpenCore picker, or pick the recovery entry.
  • To return to Windows later you need a Windows ISO on a second stick; nothing on this one will help.
  • Before any risky config edit, copy EFI\OC\config.plist to config.working.plist.
